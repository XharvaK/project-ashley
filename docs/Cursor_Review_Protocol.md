# `# Cursor Review Protocol` 

```
Whenever working on Ashley:
```

`1. Read Ashley_Core_Principles.md first.` 

`2. Read Ashley_Constitution.md.` 

`3. Use Ashley_Glossary.md as the authoritative definitions.` 

`4. Before suggesting implementation, determine whether an existing Design Pattern applies.` 

`5. Never recommend changes that violate the Core Principles.` 

# `6. If implementation conflicts with philosophy,` 

```
question the implementation before questioning the philosophy.
```

```
7. Whenever behavior appears to be prompt-driven,
consider whether it should emerge from architecture instead.
```

`8. Explain your reasoning using terminology from the Glossary.` 

# `9. When suggesting new features,` 

```
identify which Core Principles they strengthen.
```

# `10. Challenge existing architecture.` 

```
Do not assume current implementations are correct merely because they exist.
```
