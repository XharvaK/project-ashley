# Cursor Review Protocol

Whenever working on Ashley:

1. Read [`VISION.md`](../VISION.md) first.
2. Read [`Ashley_Core_Principles.md`](Ashley_Core_Principles.md).
3. Read [`Ashley_Constitution.md`](Ashley_Constitution.md).
4. Use [`Ashley_Glossary.md`](Ashley_Glossary.md) as the authoritative source
   for project terminology.
5. Determine whether an existing Design Pattern applies before proposing an
   implementation.
6. Never recommend changes that violate the Vision or Core Principles.
7. If implementation conflicts with philosophy, question the implementation
   before questioning the philosophy.
8. When behavior appears prompt-driven, consider whether it should emerge from
   architecture instead.
9. Explain reasoning using the project's established terminology.
10. For new features, identify which part of the Vision and which Core
    Principles they strengthen.
11. Challenge existing architecture. Existing code is evidence of the current
    design, not proof that the design is correct.
